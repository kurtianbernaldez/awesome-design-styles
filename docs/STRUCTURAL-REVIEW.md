# Structural review

Before replacing the original collection, three contrasting documents were inspected: a software product analysis, an editorial publication analysis, and a historical web catalog analysis. Their frontmatter, token tables, prose sections, component specifications, responsive rules, and guardrails informed the completeness checklist only.

Useful structural patterns:

- Associate each token with a role and concrete value.
- Explain type hierarchy using weight, line height, and scale together.
- Connect spacing and surface rules to actual components.
- Describe how composition changes on smaller screens.
- Include implementation constraints and specific mistakes to avoid.

Gaps to correct in the new collection:

- Some source documents omitted hover behavior or had incomplete example placeholders.
- Accessibility and motion were not consistently standalone requirements.
- Extensive metadata mixed discovery fields with visual implementation details.

The new template keeps discovery metadata small and makes interaction states, accessibility, motion, and implementation guidance explicit. No source sentences, brand palettes, layouts, fonts, components, logos, or other assets were reused. The MIT license and its original copyright notice remain unchanged.
